# 원본 진단 결과와 논문 v3.0 교차검토 요청

## 검토 대상과 결론 후보

구매·소비·잔량 및 SCI·보상 재계산은 원본과 일치했다. 그러나 기본조건 Safe Stock의
안전선 미달 판정은 부동소수점 경계에서 발생했다. 논문은 이를 실질적인 안전성 열세로
해석하지 않도록 정정했다. 이 결론의 오류·반례·과장 가능성을 검토해 달라.

원본 자료는 실제 PC에서 학습된 네 체크포인트를 진단한 CSV/JSON이다.
검토자가 바이너리 체크포인트를 갖지 않았다면 기록된 체크포인트 해시를 직접 검증한 것으로
표현하지 않는다. 상호 합의나 이전 AI의 판정은 증거로 사용하지 않는다.

후속 체크포인트 재실행 증거와 이번 소스 대조는 [제출 정리](submission_alignment_v3_0.md)를 참조한다.
Safe Stock의 `price_advantage_reward_mean≈0.007202`와 `safety_reward_mean=-0.5`는 다른 필드다.

## 함께 읽을 자료

- `reward_diagnostics_results_4seed.md`: 네 보완 자료, 수치 경계 발견, 주장 제한.
- `../../results/diagnostics/review_4seed/`: 연료수지·안전선·정책비교·급유행동 CSV와 provenance.
- `../submission/ack_paper_v3_0.md` 및 별도 DOCX: 실제 논문 반영 내용.
- 별도 전달 묶음의 `independent_reward_audit.py`, `reward_audit_verified.json`과 원본 `upload/` 16개 파일.
- 기존 환경 코드 `envs/bunkering_env.py`와 `scripts/baseline.py`, 기준 커밋 `97233c1c442a687aaed4a34e2cadca0d98aa2fb9`.

이번 작업에서 환경·보상 코드, 학습 모델, 기존 공식 결과는 변경하지 않았다.
환경 수정 및 재학습을 수행했다고 간주하지 않는다.

## 핵심 질문

1. 상한손실을 단순 잔차로 다시 정의하는 순환 검증을 피하고, 액션·소비량·상한으로
   급유량과 손실을 독립 계산했는가? 수지 일관성과 물리적 타당성을 구분했는가?
2. Safe Stock의 `0.1499999999999997 < 0.15`가 항차당 위반 1회와 -0.5를 만들었다는
   설명이 원본과 맞는가? 정확한 십진수 행동 고정 재생과 허용오차 후처리의 한계를 명시했는가?
3. 기본조건의 안전선 재분류를 소비량·horizon의 모든 조건으로 확대 주장한 곳이 있는가?
4. 1,600개 기록 중 반복 규칙을 제거한 700개 조합을 독립 시장 경로로 오인하게 하지 않는가?
   DQN은 4×100, 규칙은 각각 100이며 동일 평가 seed를 공유하는가?
5. DQN의 추가 구매 0.46325와 추가 최종잔량이 일치한다는 결과로, SCI +53.97%를
   안전성 개선이나 손실로 성급히 단정한 곳이 있는가? 최종 재고가치는 차감하지 않았다.
6. 529/1,960의 소량 급유(26.99%)와 해당 가격우위 보상 비중(57.86%)을
   보상 설계의 원인 효과로 과장했는가?
7. 논문 초록·방법·표·결론에서 같은 정의를 쓰는가? `step_sci_mean`을 항차 SCI와
   SCI/step 사이에서 혼동하지 않는가? 기존 공식 단일 체크포인트와 4개 후속 모델을 구분하는가?
8. FuelCast와 실제 항차 자료가 이번 학습·평가에 쓰였다는 오인이 있는가?

## 요청하는 답변 형식

확인한 파일과 못 읽은 파일을 먼저 구분한다. 확정 결함, 해석 위험, 미검증 가설을
나누고 각 항목에 원본 행 또는 코드·문서 위치를 제시한다. 마지막으로 논문 v3.0에
필요한 최소 수정과 후속 코드 변경을 분리해 제안한다. 실제 파일 미확인을 결함 존재나
통과의 근거로 사용하지 않는다.

## 제출 전 남은 조건

공동저자·소속·이메일을 확정해야 한다. 환경 경계 비교의 일관된 수정과 수정 보상하의
재학습 영향은 이번 자료 보완을 넘어서는 후속 과제다. 논문은 현재 결과와 이 한계를 함께
기록하며 제출 승인·수상·실무 적용을 보증하지 않는다.
