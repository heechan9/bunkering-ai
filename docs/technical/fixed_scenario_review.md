# Ocean Lab 고정 합성 시나리오 검토 MVP

구현 기준: `7884e9749ec3e497b9d495ec4e62e4466c625f8a`.

운항 체험의 **현재 단계의 구매안 비교**에서 다음 1~2단계의 기존 구매/미구매
후보에 연료·작업시간·출항 마감 검사를 함께 표시한다. 실제 항로 최적화,
운영 추천, 모델 교체 또는 공식 30단계 평가가 아니다. 기존 replay, 정책,
Python 계산기와 정본 결과는 변경하지 않는다.

## 사용

1. 운항 체험을 시작하고 검토할 재생 단계를 고른다.
2. 정상 / 마감 충돌 / 입력 누락 합성 예시를 고른다. 시각과 작업시간은 수정 가능하다.
3. 후보별 급유 전 연료, 종료 잔량, 출항/마감, 제약 판정과 보정 SCI를 확인한다.
4. 검토 JSON으로 현재 선택(정책·체크포인트·시장 사례), 관측 입력, 원문 시간 입력,
   정규화 숫자, 가정·제약·전체 정밀도 결과를 저장한다.

재생 단계를 바꾸면 현재 관측값으로 다시 계산하고 시간 가정은 유지한다.
패널을 벗어나거나 기록 끝에서 패널이 사라진 뒤 다시 열면 정상 예시로 초기화한다.
기존 선택 공유 URL은 시간 가정을 저장하지 않는다. 재사용·검토에는 JSON을 사용한다.
파일 업로드·서버 저장 기능은 추가하지 않았다.

## 연료와 비용

- 기존 `purchase-comparison.ts`의 소비 후 급유 계산을 그대로 호출한다. 소비 0.05,
  급유 요청 0.9, 급유 목표 상한 0.95, 초기량/탱크 용량 1. 화면은 ×100 단위다.
- 1.0의 초기 연료는 유효하다. 0.95는 급유 목표 상한이며 탱크 용량과 다르다.
  실제 급유량은 남은 공간으로 제한된다. 유효 범위를 벗어난 관측값은 비교하지 않는다.
- 추가 검토는 **0으로 자르기 전 급유 전 연료**를 검사한다. 부족은 `< -1e-9`,
  안전여유 미달은 `< 0.15 - 1e-9`다. 이후 급유로 앞선 부족을 상쇄하지 않는다.
  기존 replay의 1e-12 사후 잔량 표시는 변경하지 않았다.
- 구매 SCI만으로 순위를 정하지 않는다. 보정 SCI는
  `구매 SCI + (시작 연료 - 종료 연료) × 현재 가격 × 현재 환율`이다.
  시작·종료 재고에 같은 현재 가치를 적용하며 미래 replay 행을 읽지 않는다.
- 가격·환율·소비가 고정이므로 검토 구간 전체를 수행하고 검사에 통과한 후보의 2단계 보정 SCI는 모두
  `0.10 × 가격 × 환율`(1단계는 0.05)로 동률이다. 수치 허용오차 내 동률은
  같은 순위를 표시한다. 동률에서 임의의 승자를 고르지 않는다.
- 부족·안전여유·용량·마감 위반, 미실행 단계, 입력 부족/오류는 비교 가능한 SCI와
  순위를 `null`로 둔다. 진단용 회계 수치는 JSON에 별도로 남길 수 있다.
- 모든 비용은 SCI이며 실제 통화가 아니다. 경제적 우위·실제 절감은 입증되지 않았다.

정의: [안전·회계 기준](safety_accounting.md), [공식 평가](official_evaluation.md).

## 시간 계약

[`research/port_call_time/model.py`](../../research/port_call_time/model.py)의
`existing_call` 산식을 브라우저 TypeScript에 이식했다. Python intake CLI를 호출하거나
입력 형식을 그대로 가져오는 기능은 아니다. **기존 화물 기항·시간 단위·합성 입력**만
지원하는 제한된 편집기이며 실자료 입력의 출처·공개범위·자기확인 검증을 대신하지 않는다.

`출항 = max(급유 없는 출항, max(급유 영향 반영 하역 종료,
급유 준비 가능 + 준비 + 이송 + 마무리) + 모든 작업 후 출항 준비)`

- 급유 없는 기준 출항에는 동일한 출항 준비가 이미 포함된다.
- 하역 종료에는 급유 때문에 생긴 중단을 입력자가 반영해야 한다.
- 급유 준비 가능 시각은 접근 제한·대기를 포함한다. 작업은 하역과 겹칠 수 있다.
- 준비 → 이송 → 마무리는 순차이며, 출항 준비는 **모든 하역·급유 작업이 끝난 뒤**에
  시작한다. 마무리와 중복하거나 작업과 병행 가능한 시간을 다시 넣지 않는다.
- 매 구매 선택은 실제 급유량이 줄거나 0이어도 전체 고정 작업시간을 부담한다.
  이는 시연용의 명시적 '급유 시도' 가정이며 실제 작업시간 추정이 아니다.
- 미구매 후보는 급유 없는 기준 출항을 사용한다. 그 값과 마감이 있으면 미구매만 있는
  경로는 급유 작업시간 누락과 무관하게 계산 가능하다. 구매가 있는 단계에서는 누락을
  0으로 채우지 않고 UNKNOWN/입력 부족으로 전파한다.
- 모든 입력 시각은 기항별 같은 0을 기준으로 한 offset이다. 같은 양식을 각 단계에
  반복 적용한다. 단계 간격은 가정상 24h이고 앞 단계의 추가 지연은 회복 없이 누적한다.
  표의 출항/마감은 **검토 시작 기준**으로 첫 단계 0h, 둘째 단계 24h에 더한 값이다.
- 마감과 같은 시각은 허용한다. 각 실행 단계가 모두 마감을 만족해야 한다.
- 빈칸·null·누락은 UNKNOWN. 명시적 숫자 0만 0으로 계산한다. 음수·NaN·Infinity·
  숫자가 아닌 값·산술 범위 초과는 오류로 분리한다.
- 출항 준비 없는 Python의 과거 호환 호출을 따르지 않는다. 브라우저의 구매 경로에는
  출항 준비가 필수다([intake 계약](../../research/port_call_time/INTAKE.md)).

급유량별 이송시간·항만 공급·연료 규격·조석·도선사·선석·실항차 이동시간·대기 소비·
지연에 따른 소비 변화·후속 일정 재조정은 모델링하지 않는다. 시간 편집값은 합성 가정이며
진위나 이중계산 부재를 코드가 확인했다고 주장하지 않는다.

## 손계산 예시

기본: 기준 출항12, 하역 종료10, 급유 가능0, 준비1, 이송8, 마무리1, 출항 준비2,
마감14 (모두 h).

- 정상: 급유 종료10, 출항12, 추가0. 두 번째 출항36 ≤ 마감38.
- 마감 충돌: 급유 가능8 → 급유 종료18 → 출항20 > 마감14, 추가8.
  다음 미구매 출항은 24 + 8 + 12 = 44 > 38. 이전 지연을 잊지 않는다.
- 누락: 이송·출항 준비가 빈칸이면 구매 경로는 보류. 미구매→미구매는
  기준 출항·마감이 완전하면 계산한다.
- 출항 준비 반례: 기준12, 하역13, 급유 종료10, 출항 준비2 → 출항15, 추가3.
- 연료0.03에서 구매: 소비0.05로 0.02 부족. 나중에 0.9까지 급유하더라도 제외.
- 연료0.5·가격500·환율1300의 안전한 2단계: 서로 구매량이 달라도 보정 SCI65,000.

## 회귀검사

웹 디렉터리에서:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm check:regressions
pnpm build
```

`check:regressions`에는 `scripts/check-scenario-review.mjs`가 포함된다. 해당 스크립트는
실제 TypeScript 모듈을 로드하여 위 반례, 경계·누락·잘못된 입력·용량, 이전 지연 누적,
단일 잔여 단계, 고갈, 부동소수점 동률, 내보내기와 반복사용, 미래 기록 비사용을 검사한다.
추가로 번들된 19,030개 결정 시점 전체를 대조한다. 실제 모바일·다른 브라우저·실선 데이터
검증이나 모델 재학습을 의미하지 않는다.
