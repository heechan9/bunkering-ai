# 항차 CSV 검토·원자료 변경 감지·웹 요약 생성

2026-09-21 구현. 새 실측 자료나 새 모델 실험이 아니라 자료 수령과 검토를 위한 도구다. 논문은 v5.0 유지.

## 웹: 전략 비교 → 항차 CSV 자료 검토

파일은 브라우저 메모리에서만 읽고 서버로 보내거나 영구 저장하지 않는다. 새로고침하면 비교 기준도 사라진다. 5MB·10,000행·100열 제한, UTF-8/CP949 명시 선택, 중복 헤더·잘못된 따옴표·불일치 열 개수 거부. 선택한 인코딩이 다르면 다시 선택한다.

빈 양식을 다운로드하고 선박/항차/연료별 한 행으로 정리한다. 원자료는 별도로 보존한다. 원본이 여러 공급 이벤트로 나뉘면 이 도구가 자동으로 같은 항차라고 추정하거나 합산하지 않는다. 공통 식별자와 집계 근거를 먼저 확인한다.

| 필드 | 의미 |
|---|---|
| vessel_id, voyage_id, fuel_type | 확인된 선박·항차·연료 식별자 |
| departure_at, arrival_at | 시간대 포함 ISO 8601 시각(예: 2026-09-01T00:00:00+09:00) |
| unit | 한 행 네 수량의 공통 단위: t, kg, m3, L |
| opening, supplied, consumed, closing | 출발잔량·실제급유량·소비량·도착잔량. 빈칸을 0으로 바꾸지 않음 |
| supply_basis | 실제 공급량임을 확인한 경우 actual. 예정/신청/미확인은 보류 |
| source_ref | 원자료 파일명·페이지 등 확인 근거 |

음수·비수치·미확인 단위·중복 항차/연료·날짜 오류는 held로 보류한다. 통과한 행만 opening + supplied - consumed - closing을 계산한다. 허용오차는 사용자가 입력한 행 단위의 절대 오차이며 기본 0.01은 공식 운항 기준이 아니다. 질량과 부피를 변환·통합하지 않는다. balanced는 수지 일치일 뿐 출처 진위·실선 안전성·모델 우수성을 의미하지 않는다.

비교 기준은 사용자가 명시적으로 지정한다. 새 CSV와 기준의 SHA-256 및 행 식별자를 대조해 추가·삭제·변경을 표시한다. 중복 식별자가 있으면 행 변경 비교를 보류한다. 결과 CSV에는 원본 해시·허용오차·보류 이유를 넣고, 수식으로 실행될 수 있는 문자열은 앞에 따옴표를 붙인다. 따라서 다운로드 결과는 원본의 바이트 보존 사본이 아니다.

## 저장소 파일 변경 감지

기존 공개자료 기준: `docs/data/source_baseline.json`.

```
python scripts/source_changes.py data/public docs/data/source_baseline.json
```

추가/삭제/변경이면 종료코드 1, 동일하면 0. 기준을 자동 덮어쓰지 않는다. 새 수령 디렉터리는 외부 경로의 새 baseline을 `--create`로 명시적으로 생성한다. 기존 baseline 덮어쓰기는 거부한다. 비공개 항차 자료와 그 메타데이터를 공개 저장소에 올리지 않는다.

## 정본에서 웹 요약 생성

```
python -m scripts.build_web_summary
python -m scripts.build_web_summary --check
```

연구 CSV에서 research-summary.json을 생성하고 웹 비교표가 이를 읽는다. 기존 대조 검사를 먼저 통과해야 생성하며, 새 실험이 들어오면 먼저 정본-재생의 전체 검토를 갱신해야 한다. 전이 자료를 새로 생성하거나 과거 replay 검증 해시를 자동 승인하지 않는다. CI는 생성값과 정본의 불일치를 감지한다.

CSV 파싱·0/빈칸·중복·단위·실공급 여부·잘못된 날짜·수지 차이·수식 방어·CP949 검사, 파일 추가/삭제/변경 검사, 웹 타입·번역/수치 회귀 및 프로덕션 빌드를 수행했다. 실제 해기원 자료와 사용자의 모바일 파일 선택·다운로드 동작은 미검증이다.

## 자료 목록과 열별 점검 (2026-09-21 추가)

전략 비교에서 '자료 출처·확인 상태'를 열면 합성환경 결과, 울산항 공개자료, 민재의 정성 검토, 해기원 자료 수령 대기를 확인할 수 있다. 근거는 검토 당시 고정 Git revision으로 연결하며 실시간 수령 상태가 아니다. 새로운 자료 수령 시 목록도 검토 후 갱신해야 한다.

항차 CSV 검토는 열마다 전체 행 수, 빈칸, 값이 있지만 오류 또는 미확인인 개수를 구분한다. 빈칸을 오류 개수에 중복 집계하지 않고 숫자 0을 누락으로 처리하지 않는다. 단위와 실제 공급 여부는 기존 행별 규칙과 동일하다. 중복 식별자, 시각 순서, 수지 차이는 여러 열의 관계이므로 행별 결과에서 확인한다. 텍스트가 채워져 있어도 출처 진위나 항차 식별 정확성을 인증하지 않는다. 양식이 맞지 않으면 요약을 만들지 않는다. 열별 요약 CSV에는 입력 파일 SHA-256을 포함한다.

참고 구현: heechan9/triguard-ai의 public-statistics/analysis-workbench.js (528a7c3826cdceab5a7615bb6ba324198b41669a). 기존 코드 복제 없이 병커시유의 검토 규칙에 맞춰 구현했다. 정책 비교 확장과 논문 본문 변경은 이번 범위에 포함하지 않았다.
