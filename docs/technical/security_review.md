# 정적 보안 검토 현황과 후속 점검 계획

## 상태 요약

2026-09-11 기준 Codex Security 정적 검토에서 **현재 검토 범위 내 확정된 보안 취약점은 0건**이었다.

이 결과는 현재 저장소가 지향하는 **로컬 강화학습 실험 도구** 범위에 대한 정적 검토 결과다. 실제 실행 기반의 동적 분석, 침투 테스트, 의존성 CVE 검사는 포함하지 않았으므로 “보안이 완전히 검증되었다”거나 “운영환경 배포가 안전하다”는 뜻이 아니다.

## 검토 범위

- Python 파일 23개
- Jupyter Notebook 2개
- 설정 파일
- 인수인계용 압축파일 내부 코드

검토는 소스와 설정을 대상으로 한 정적 분석이며, 현재 확인된 구현에서 확정 가능한 취약점을 찾는 데 초점을 두었다.

## 이번 검토에서 확인하지 않은 항목

| 미실시 항목 | 의미 | 수행 시점 |
|---|---|---|
| 동적 실행 보안시험 | 실제 실행 중 파일·프로세스·네트워크 동작과 예외 경로 확인 | 외부 입력이나 자동화 실행 범위가 늘어날 때 |
| 침투 테스트 | 공격자 관점에서 인증 우회·입력 변조·자원 고갈 등을 시험 | 웹/API 또는 다중 사용자 서비스 전환 전 |
| 의존성 CVE 검사 | 설치된 패키지와 잠금된 버전의 공개 취약점 확인 | 제출 전 1회 및 의존성 변경 시 |
| 배포환경 점검 | 운영체제·컨테이너·클라우드 권한과 비밀정보 관리 확인 | 실제 배포환경이 정해진 뒤 |

따라서 문서와 발표에서는 다음과 같이 제한해 표현한다.

> 정적 검토 범위에서 확정된 보안 취약점은 발견되지 않았다. 동적 분석, 침투 테스트 및 의존성 CVE 검사는 별도 범위다.

## 다음 단계 점검 항목

### 1. 현재 로컬 실험 도구

현재 기능을 유지하는 동안에는 아래 항목을 우선한다.

- 의존성 버전 고정 여부를 확인하고 CVE 스캔 결과와 실행일을 기록한다.
- 체크포인트와 외부 파일의 출처·해시를 기록하고, 신뢰하지 않는 직렬화 파일을 로드하지 않는다.
- 경로 인수는 작업 디렉터리 밖의 파일을 의도치 않게 덮어쓰지 않는지 확인한다.
- 오류 메시지와 로그에 토큰, 로컬 사용자 경로, 환경변수 등 민감정보가 포함되지 않는지 확인한다.
- 압축파일을 자동 해제하는 기능을 만들 경우 경로 순회(Zip Slip), 심볼릭 링크, 압축 폭탄을 방어한다.
- 보안 점검 결과는 날짜, 커밋 SHA, 도구 버전, 대상 파일 목록과 함께 보존한다.

### 2. 외부 CSV 입력 및 Excel 공유 기능을 추가할 때

해당 기능이 구현되기 전까지는 설계 체크리스트이며, 현재 구현 완료를 의미하지 않는다.

- 허용 확장자만 보지 말고 실제 파일 형식, 인코딩, 열 이름, 자료형을 검증한다.
- 파일 크기, 행 수, 열 수, 필드 길이에 상한을 둔다.
- 결측값·무한대·비정상 범위·중복 열·예상 밖 열을 명시적으로 처리한다.
- 출력 셀이 `=`, `+`, `-`, `@` 또는 탭·개행 같은 제어문자로 시작하면 스프레드시트 수식으로 실행되지 않도록 안전하게 이스케이프한다.
- 원본 입력과 정제된 출력의 해시·처리 이력을 남기고 원본 파일을 실행하거나 매크로 허용 형식으로 변환하지 않는다.
- 악성 CSV 예제와 경계값을 자동 테스트에 포함한다.

### 3. 웹/API 서비스로 확장할 때

웹/API가 생기면 로컬 도구의 현재 검토 결과를 그대로 적용할 수 없으므로 별도 위협 모델과 보안시험이 필요하다.

- 인증: 계정·토큰 수명, 비밀번호 정책, 세션 폐기
- 권한: 사용자·프로젝트·파일별 접근통제와 IDOR 방지
- 업로드: 파일 형식·크기·저장경로·악성 콘텐츠·경로 순회 방어
- 입력 처리: 스키마 검증, 명령·경로·템플릿 주입 방어
- 자원 제한: 요청 크기, 학습·평가 실행시간, 동시 작업 수, 저장공간, rate limit
- 비밀정보: API 키를 코드·로그·결과물에서 분리하고 최소권한으로 관리
- 네트워크: CORS·CSRF·TLS·외부 호출 대상 제한을 서비스 구조에 맞게 점검
- 관측성과 대응: 감사로그, 보안 이벤트 알림, 백업·복구, 취약점 신고 절차
- 배포 전 검증: SAST, dependency scan, secret scan, DAST와 수동 침투 테스트

## 완료 기준

후속 보안 점검은 단순히 도구를 실행한 사실이 아니라 다음 근거를 남겼을 때 완료로 본다.

1. 대상 커밋 SHA와 점검 날짜
2. 사용 도구와 버전
3. 검사 범위 및 제외 범위
4. 발견사항, 심각도, 조치 또는 수용 근거
5. 재검사 결과
6. 잔여 위험과 다음 점검 시점

이 문서는 개발 현황과 보안 주장 경계를 관리하기 위한 문서이며, 논문의 성능 결과나 기존 평가 정본을 변경하지 않는다.
