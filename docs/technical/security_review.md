# 정적 보안 검토 현황과 후속 점검 계획

## 1. 개발 현황 반영

2026-09-11 Codex Security 저장소 정적 감사 결과, **보고 가능한 확정 보안 취약점은 0건**이었다.

이 문장은 아래 범위와 한계를 항상 함께 전제로 한다.

- 현재 대상은 로컬 Python 강화학습 연구 프로토타입이다.
- 감사 커버리지는 `partial`이다.
- 대상 코드·테스트·노트북을 실행하거나 원본을 수정하지 않은 오프라인 정적 소스 검토다.
- 실제 실행 기반 검증, 침투 테스트, 설치된 의존성의 최신 CVE 대조는 수행하지 않았다.
- 향후 웹/API, 다중 사용자 환경, 외부 데이터 수신 구조의 안전성을 보증하지 않는다.

따라서 README·발표·개발보고서에서 허용하는 표현은 다음과 같다.

> 2026-09-11 오프라인 정적 소스 감사의 부분 커버리지 범위에서 보고 가능한 확정 취약점은 발견되지 않았다. 동적 분석, 침투 테스트 및 설치 의존성 CVE 검사는 별도 범위다.

“보안이 완전히 검증되었다”, “취약점이 없다”, “운영 배포가 안전하다”는 표현은 사용하지 않는다.

| 운영환경 | OS·Conda·사용자 site-packages·배포권한 미검증 | 개발자 실행환경과 설치 패키지 위험은 별도 점검 필요 |
| 사용량 | 토큰 사용량 측정 없음 | 보안 결과와 무관하며 비용·자원 보고에는 사용 불가 |

## 5. 위협 모델 요약

현재 활성 제품은 합성 선박 급유 시뮬레이션, Rule-based 평가, Double DQN
학습을 개발자가 로컬 CLI로 실행하는 연구 프로토타입이다. 검사된 활성
코드에는 웹 서버, 인증 세션, 다중 사용자 경계, 실시간 거래·선박 제어 연결이
없다.

주요 신뢰 경계는 다음과 같다.

1. 운영자가 선택한 YAML → 구성·연산자원·환경·에이전트
2. 운영자가 선택한 CSV → pandas/date parsing → 파생 CSV·PNG
3. 운영자가 선택한 출력 경로 → 로컬 파일시스템 쓰기
4. Python 의존성과 사용자 site-packages → 개발자 권한으로 코드 실행
5. 환경과 에이전트의 동일 프로세스 경계 → 시뮬레이션 상태·행동·모델 파라미터

`yaml.safe_load`, CSV 열·날짜 검증, 환경 범위검사 등은 확인됐지만 이것들은
현재 로컬 실험 경계의 안전·정확성 통제다. 실제 선박 운항 안전, 금융거래 보안,
공유 서비스의 접근통제를 의미하지 않는다.

## 6. 확정 취약점과 보완 후보의 구분

### A. 확정된 보안 취약점

**없음 — 보고 가능한 findings 0건.**

아래 B·C 항목을 발견 취약점 수에 포함하거나 “보안 결함이 발견됐다”고
표현하지 않는다.

### B. 현재 관찰된 특성 및 예방적 보완 후보

| 항목 | 보고서 판단 | 권장 조치 |
|---|---|---|
| `requirements.txt` 버전 미고정 | 설치 취약점은 검증되지 않았으며 확정 취약점 아님 | 재현용 잠금파일 또는 설치 버전 스냅샷을 만들고 CVE 검사 |
| 공개 CSV digest 런타임 미강제 | 문서상 provenance이며 bundled digest는 감사에서 일치, 악용사례 미확립 | 필요 시 선택적 `--expected-sha256` 검증 설계 |
| 공공데이터 분석 경로가 CWD 기준 | 동일 권한 로컬 운영자의 경로 의미, 권한상승 아님 | 경로를 출력하고 문서·테스트에서 실행 위치 명확화 |
| 출력 경로 sandbox 없음 | 운영자가 이미 가진 파일 권한으로 쓰며 취약점 아님 | 공유·자동 실행 시 허용 루트와 덮어쓰기 정책 추가 |
| 환경 행동 검증 일부가 `assert` | 현재 시뮬레이션 정확성 관심사항 | 최적화 모드까지 고려하면 명시적 예외로 전환 검토 |
| 연산 하이퍼파라미터 상한 없음 | 로컬 운영자 자원 선택이며 취약점 아님 | 원격 작업큐·웹 API 도입 시 시간·메모리·동시성 제한 |
| 사용자 site-packages 실행 | 현재 개발자 권한의 로컬 의존성 경계 | 격리 환경, 해시/잠금, 신뢰 저장소 사용 |

### C. 아직 확인하지 않은 사항

- 설치된 정확한 의존성 버전과 최신 CVE
- 실제 실행 중 파일·프로세스·네트워크 동작
- Git 이력 및 과거 커밋의 비밀정보
- Notebook 과거 출력과 제외된 바이너리 문서
- 실제 배포환경·OS·Conda·사용자 site-packages 권한
- 웹/API·외부 업로드·다중 사용자 경계
- 악성 입력을 사용한 동적 자원고갈 및 오류경로

감사 보고서의 Scan Summary는 `completed`라고 기록하지만 Open Questions에는
“`remaining_auxiliary` 검토 진행 중”이라는 후속 문구가 남아 있다. 이는 확정
취약점이 아니라 **감사 산출물 상태의 불일치/증적 공백**이다. 최종 외부 제출용
보안 주장에 사용하기 전 `coverage.json`과 후속 검토 종료 여부를 대조해 이
문구를 닫거나, 미완료 범위로 계속 명시해야 한다.

## 7. 단계별 후속 보안 점검

### P1 — 다음 제출 또는 릴리스 전

- 대상 커밋 SHA와 감사 스냅샷 digest를 연결한다.
- `pip-audit` 또는 동등 도구로 실제 설치 버전의 CVE를 검사한다.
- Git 현재 트리와 필요 시 이력에 대해 secret scan을 수행한다.
- `scan-manifest.json`, `findings.json`, `coverage.json`을 보존한다.
- `remaining_auxiliary` 후속 상태를 확인하고 coverage 설명을 확정한다.

### P1 — 외부 CSV 입력·Excel 공유 기능 추가와 동시에

- 파일 크기·행/열 수·필드 길이·인코딩·열 이름·자료형을 제한한다.
- 허용값과 날짜·수치 범위를 검증하고 예상 밖 열·중복 열을 거부한다.
- 셀이 `=`, `+`, `-`, `@` 또는 탭·개행 같은 제어문자로 시작하면
  스프레드시트 수식으로 실행되지 않도록 무해화한다.
- 원본과 정제 산출물의 digest 및 처리 이력을 기록한다.
- 수식 주입, 과대 파일, 깨진 인코딩, 중복 열, 비정상 숫자를 자동 테스트한다.

현재 bundled UPA CSV의 `입항구분명`은 제한된 값이며 수식 접두 셀이 없고
문서화된 digest도 일치했다. 외부 불신 CSV를 받아 다른 사람에게 스프레드시트로
배포하는 흐름은 현재 확인되지 않았으므로 위 항목은 예방적 설계 요구사항이다.

### P1 — 웹/API 개발 착수 전

- 위협 모델과 데이터 흐름도 작성
- 인증·세션 수명·로그아웃 정책
- 사용자·프로젝트·파일별 권한과 IDOR 방지
- 업로드 파일 형식·크기·저장경로·경로 순회 방어
- 요청 크기·학습시간·메모리·동시 작업·저장공간·rate limit
- API 키·토큰·비밀정보의 코드·로그·결과물 분리
- CORS·CSRF·TLS·외부 호출 대상 제한
- 감사로그·보안 알림·백업·복구·취약점 신고 절차

### P2 — 외부 노출 실행환경 구축 후

- 악성 입력 기반 동적 분석
- DAST 및 수동 침투 테스트
- 압축파일 자동 해제 시 Zip Slip·심볼릭 링크·압축 폭탄 시험
- 자원고갈·동시성·장시간 학습 작업 취소/회수 시험
- 복구 절차와 사고 대응 훈련

## 8. 완료 증적

후속 점검은 아래를 남겼을 때 완료로 판정한다.

1. 대상 Git 커밋 SHA, Target ID, Snapshot digest, 점검 날짜
2. 사용 도구와 버전
3. 대상 파일 목록과 제외 범위
4. 발견사항, 심각도, 조치 또는 위험 수용 근거
5. 재검사 결과
6. 잔여 위험과 다음 점검 시점

이 문서는 개발 현황과 보안 주장 경계를 관리한다. 논문의 성능 수치, 기존
평가 정본, 체크포인트 또는 모델의 운항 타당성을 변경하지 않는다.
