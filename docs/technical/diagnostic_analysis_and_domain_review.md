# 행동 진단 집계와 도메인 자문 준비

## 현재 상태와 범위

학습 체크포인트 4개의 상세 진단 출력은 아직 전달되지 않았다.
이 문서는 결과를 미리 주장하지 않으며 공식 평가·보상·환경을 변경하지 않는다.
새 집계 도구의 시험 데이터는 검증용 fixture로서 학습 결과가 아니다.

2026-09-11 검증: 새 집계 테스트 6개 통과, 격리 worktree에서 전체
`python -m pytest -q` 결과 **215 passed in 10.02s** (기존 209 + 신규 6).
이는 집계 도구 검증이며 실제 학습 체크포인트 4개의 결과 검증은 아니다.

## 출력 전달 후 실행

Anaconda Prompt에서 진단 폴더 4개가 준비된 후 실행한다.

```bat
python -m scripts.summarize_reward_diagnostics --inputs results\diagnostics\reward_seed_42 results\diagnostics\reward_seed_1042 results\diagnostics\reward_seed_2042 results\diagnostics\reward_seed_3042 --output-dir results\diagnostics\comparison_v1
```

새 출력 경로만 허용한다. 입력은 읽기만 하며 다음을 생성한다.

- `policy_summary.csv`: 규칙 정책 각 1행, DQN 체크포인트별 1행.
- `dqn_checkpoint_summary.csv`: 체크포인트별 episode 평균 지표의 평균·ddof=0 표준편차·최솟값·최댓값. 신뢰구간이 아니다.
- `case_trace.csv`: 기본적으로 base seed의 시점별 기록. 통계적 대표성을 주장하지 않는 설명용 사례다.
- `manifest.json`: 입력 파일 해시·체크포인트 해시·평가 사례 수·사례 선택 기준.

체크포인트 SHA 중복, 평가 조건 불일치, 빠진 사례, 비유한 값,
episode/step 합계 불일치, 연료수지 불일치를 거부한다.
해시는 출처 식별용이며 학습 seed 독립성이나 5,000회 학습 사실을 자체 입증하지 않는다.
반복 규칙 결과가 다르면 집계를 중단한다. 동일한 규칙 반복을 표본수 증가로 세지 않는다.

## 분석 순서와 해석 규칙

1. 도착률과 연료고갈 여부를 먼저 확인한다. 실패 항해의 낮은 SCI를 효율성으로 해석하지 않는다.
2. 안전위반 episode 비율(1회 이상), episode당 위반 step 수,
   전체 실행 step 중 위반 비율을 구분한다. 조기 종료는 노출 길이를 줄이므로 단독 순위에 쓰지 않는다.
3. SCI·구매량·급유횟수·최종잔량·보상 성분을 함께 비교한다.
4. 설명용 동일 사례에서 시점별 잔량·구매량·가격을 대조한다.
   최종 잔량만으로 구매 타이밍의 인과효과를 판단하지 않는다.
5. 비용/안전 산점도는 관찰한 정책의 위치를 보여준다. 전체 최적 경계나 최적해 근접성을 주장하지 않는다.

DQN이 열세라면 “시험한 설정에서 DQN의 우위를 확인하지 못했다”고 기록한다.
상태정보 부족·보상 설계·학습 부족 중 어느 하나를 별도 실험 없이 원인으로 확정하지 않는다.
구매량 비례가 아닌 가격 보상과 소량 다회 구매의 동시 관찰은 인과관계 증명이 아니다.
소비량 조건은 -10%, 기준, +10%, +20%이며 -20%는 기존 실험에 없다.

## 민재 도메인 자문 질문지

검토자 이름·관련 교육/경험·검토일·읽은 파일/버전을 기록한다.
검토자는 각 답변을 근거 있음 / 경험상 의견 / 확인 불가로 구분한다.

| 질문 | 요청하는 답변 |
|---|---|
| 실제 구매 담당자는 언제 무엇을 결정하는가? | 의사결정 시점·주체·필수 정보의 구체적 예 |
| 현재 안전잔량 0.15라는 가정은 무엇이 빠져 있는가? | 선박·항차별 기준 차이와 필요한 자료. 실제 안전기준 승인으로 해석하지 않음 |
| 출발 시 탱크가 가득 찬 상태는 어떤 상황을 대변하는가? | Fixed Fueling 비교의 적용 범위와 빠진 사례 |
| 실제 급유에는 어떤 제약이 우선인가? | 항만 공급·최소 주문량·급유 소요시간 등 상위 3개와 근거 |
| 구매비용과 최종 잔량은 현장에서 어떻게 함께 판단하는가? | 재고가치·다음 항차·연료 규격 관련 확인 사항 |
| 비교표가 실제 업무의 어떤 질문에 도움이 되는가? | 유용한 출력 1개, 부족한 출력 1개 |
| 최소 현장 검증에 필요한 자료는 무엇인가? | 익명화 가능한 항차·구매·잔량 데이터 항목과 단위 |

자문은 모델 가정에 대한 의견이며 현장 성능 검증이나 비용절감 실증이 아니다.
자문받지 않은 상태에서 “실무자 검증 완료”라고 쓰지 않는다.

학습 기반 정책의 도착률과 합성 구매비용 지표를 비교한다. 보충 진단에서는

마지막 문장은 학습 체크포인트 진단 완료 전에는 연구방법/계획으로만 사용한다.
실제 안전상 우위·개선폭은 결과 확인 후 작성한다. 논문 DOCX 수정 완료를 뜻하지 않는다.

“재현 가능한 정책 비교 구조는 후속 항차 자료 검증의 기반을 제공한다.
실제 비용절감과 공급망 대응 효과는 현장 자료를 이용한 별도 검증이 필요하다.”

## 신규 예방형 규칙을 추가할 경우

기존 결과를 참고한 설계임을 공개하고 임계값 선택과 최종 평가를 분리한다.
모든 정책에 동일하게 제공되는 관측정보만 사용하며, 미관측 스트레스 소비량을
규칙에만 알려주지 않는다. 이미 확인한 42~141 사례는 탐색 자료로 표시하고,
추가 비교를 확정할 때 새 평가 사례·표본수·선택 절차를 결과 확인 전에 고정한다.
기존 공식 결과를 덮어쓰지 않는다. 이 문서는 신규 규칙 구현 또는 재학습을 포함하지 않는다.
