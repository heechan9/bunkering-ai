## 적용한 기능

| FabGuard 근거 | 병커시유 적용 |
|---|---|
| `web/smt/evidence-model.mjs`의 자료 종류·기간·단위·집계 범위 | 자료 출처 카드 4개에 한·영으로 구분 표시 |
| 같은 파일의 `sourceUrl` | 검토한 커밋으로 고정된 근거 링크 |
| `scripts/build_web_evidence.py` | 검토한 문서 해시와 일치할 때만 자료 목록 생성, `--check`로 stale 출력 거부 |
| 공개 evidence snapshot | 비공개 원본을 포함하지 않는 자료 목록 JSON 다운로드 |

코드를 그대로 복제하지 않고 병커시유의 기존 자료 출처 화면에 맞춰 구현했다.
검토일과 자료 기간을 분리한다. 근거 문서 해시는 비공개 원본의 해시나 진위 인증이 아니다.

## 기존 구현으로 충족

- 파일 업로드·원본 바이트 해시·수치/누락 검사·이전 파일 비교: `VoyageReview.tsx`, `lib/voyage-csv.ts`.
- 가정값의 영향 비교: `AbLogReview.tsx`의 날짜 범위 및 밀도 시나리오.
- 저장 결과와 웹 수치 대조: `scripts/audit_web_evidence.py`, 직전 PR #68의 실행 기록.

## 적용하지 않은 기능과 이유

- SECOM 분류·Top-K 위험순위·불량 비용 계산: 급유 행동 공간 및 비용 정의와 달라 검증 없이 이식할 수 없다.
- SMT 검사·SPC·장비/태양광 파이프라인: 해당 계측 및 공정 조건이 병커시유에 없다.
- 3D 공장 장면·교육용 검사 사례: 해양 지형·선박 UI에 필요한 기능이 아니다.
- 제조 설명변수/위험 점수를 급유 원인 또는 성공확률로 표현하지 않는다.

## 갱신 절차

1. 정본 문서 변경을 검토하고 `scripts/web_source_catalog.json`의 설명·SHA-256·revision을 함께 갱신한다.
2. revision은 해당 문서가 보관된 실제 Git 커밋을 사용한다.
3. `python scripts/build_source_catalog.py` 후 `--check` 및 테스트를 실행한다.
4. 생성된 JSON과 설정을 함께 커밋한다. 문서만 바뀌면 CI에서 실패하도록 구성했다.

논문·학습·평가 조건·수치·비공개 원본은 변경하지 않는다.
