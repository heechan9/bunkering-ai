# 병커시유 직무 연계와 인터뷰 가이드

이 문서는 병커시유의 구현 증거를 해운·물류 최적화, 산업 AI, 강화학습 및 운영 의사결정 직무의 언어로 설명하기 위한 포트폴리오 보조자료다. 채용·교육 자료는 설명 구조를 정하는 참고자료이며 프로젝트 성능의 기술적 증거가 아니다.

## 한 문장 정의

병커시유는 합성 항해 환경에서 연료가격·환율·연료잔량·잔여항로를 상태로 사용해 급유 의사결정을 실험하고, Rule-based baseline과 Double DQN 학습 파이프라인을 검증하는 연구용 의사결정 지원 프로토타입이다.

## 직무 키워드에서 검증 증거까지

| 직무 키워드 | 프로젝트에서 수행한 행동 | 확인 가능한 증거 | 주장하지 않을 내용 |
|---|---|---|---|
| 운영 문제 모델링 | 6개 상태변수, 급유 행동, 보상·비용·종료 계약을 Gymnasium 환경으로 구현 | `envs/bunkering_env.py`, 상태·행동·보상 명세 | 실제 선박 또는 해운사 운영환경과 동일하다는 주장 |
| 기준선 설계 | Fixed·Price-reactive·Safe Stock을 동일 seed에서 비교 가능하게 구현 | `scripts/baseline.py`, baseline 테스트 | Rule-based가 실제 운항에서 최적이라는 주장 |
| 안전 제약 반영 | 현재 연료잔량과 안전재고 임계값만 사용하는 Safe Stock 전략을 구현 | Safe Stock 코드·경계값 회귀테스트 | 항만·급유량까지 최적화했다는 주장 |
| 강화학습 구현 | replay buffer, ε-greedy, online/target network를 포함한 Double DQN 학습 파이프라인 구현 | `agents/`, `scripts/train.py`, DQN 테스트 | DQN이 Rule-based보다 우수하다는 주장 |
| 종료 의미 구분 | 실제 terminal failure와 시간제한 truncation을 분리해 bootstrap 계약을 보존 | 학습 코드·truncation 테스트·DQN 설계 문서 | 장기 학습의 수렴이나 일반화 성능 확정 |
| 공공데이터 감사 | 울산항 벙커링정박지 신청현황 6,028건의 구조·품질·분포를 재현 가능하게 분석 | `docs/data/upa_bunkering_anchorage.md`, `results/public_data/` | 공공데이터를 DQN 학습·공식 평가에 사용했다는 주장 |
| 결과·한계 관리 | 합성 비용지수와 실제 화폐 비용을 구분하고 provisional 결과를 명시 | 기술명세·README·PR 기록 | 실제 비용절감액·절감률·탄소감축 효과 |

## 직무별 연결

### 해운·물류 운영 최적화

강조할 역량은 복수 운영변수의 상태화, 제한조건을 포함한 의사결정 규칙, 동일 조건 비교, 실패 이유 기록이다. 실제 항로·선박·항만 데이터와 연동하지 않았으므로 운영 실증 경험으로 표현하지 않는다.

### 산업 AI·스마트 물류

강조할 역량은 환경과 정책의 인터페이스 설계, 재현 가능한 seed 평가, 결과 CSV 계약, 테스트를 통한 변경 안전성이다. AI가 자동으로 급유를 집행하는 시스템이 아니라 운영자가 검토할 정책 후보를 비교하는 실험 구조로 설명한다.

### 강화학습·AI 엔지니어링

강조할 역량은 Double DQN 구성, replay buffer, target network, ε-greedy, terminal/truncation 구분이다. 현재 공식 동일조건 장기 성능평가가 없으므로 알고리즘 우월성보다 구현·검증 계약을 중심으로 설명한다.

## 자소서 경험 구성

1. **상황:** 연료가격·환율·안전재고·잔여항로가 함께 작용해 급유 시점을 단일 규칙으로 설명하기 어렵다.
2. **문제:** 실제 데이터와 공통 평가가 확정되지 않은 상태에서 RL 성능을 과장하지 않으면서도 비교 가능한 환경과 기준선이 필요했다.
3. **행동:** Gymnasium 환경, 세 Rule-based 전략, Double DQN 파이프라인, 종료 의미와 비용 계산 시점 테스트, 공공데이터 감사를 구현·통합했다.
4. **결과:** Safe Stock은 seed 42~61의 현재 합성환경에서 20/20 도착했지만 provisional M1 Reference 후보로 유지했다. 공식 회귀검증은 저장소 기술명세에 기록된 범위에서 통과했다.
5. **한계:** 항만별 가격·전이, 가변 급유량, 실제 선박 탱크·운항 데이터, 공식 DQN 대 baseline 동일조건 비교가 없다.
6. **향후계획:** 공통 seed 확대, Reference 승인, 실제 항로·항만·선박 제약 연결 후 비용·안전·운항 KPI를 별도 검증한다.

## 예상 꼬리질문

### 왜 Safe Stock을 기준선 후보로 선택했나?

미래 가격을 보지 않고 현재 관측 가능한 연료잔량과 기존 안전 임계값만 사용하면서 현재 합성환경에서 항해 성공을 안정적으로 확인했기 때문이다. 다만 20개 seed 결과만으로 일반화하거나 비용 효율성을 확정하지 않는다.

### DQN이 더 좋은가?

아직 말할 수 없다. 학습 파이프라인과 핵심 계약은 구현했지만 Rule-based와의 공식 동일조건 장기 평가가 완료되지 않았다.

### 비용절감 효과는 얼마인가?

현재 `cumulative_cost_index`는 정규화 탱크 기반 Synthetic Cost Index다. 실제 탱크 용량·통화·운영비가 연결되지 않았으므로 실제 금액이나 절감률로 해석하지 않는다.

### 본인의 역할과 AI 에이전트의 역할은 무엇인가?

프로젝트 책임자는 문제·실험 범위, 자료 선별, 결과 검토와 통합을 담당했다. 구현자와 AI 에이전트의 코드·문서 작업은 Git 작성자와 PR 역할 기록으로 구분하고, 병합자를 원 코드 작성자로 간주하지 않는다.

## 지원 전 점검표

- 최신 JD의 운항·물류·최적화 업무 문장을 실제 구현 증거와 연결했는가?
- 합성환경 결과와 공공데이터 분석을 섞지 않았는가?
- Safe Stock 20/20의 seed·환경·provisional 조건을 함께 밝혔는가?
- DQN 우월성, 실제 비용절감, 실시간 연동을 주장하지 않았는가?
- 개인·팀원·AI 에이전트의 역할을 Git 기록과 일치하게 설명했는가?

## 참고 범위

자소서·이력 점검 자료에서는 직무 키워드를 구체적 행동과 검증 증거로 연결하고, 상황·문제·행동·결과·한계·향후계획으로 경험을 구성하는 원칙만 참고했다. 강의 예문·표·양식은 복제하지 않으며 기술 성능의 근거로 사용하지 않는다.
