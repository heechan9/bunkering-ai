# 운영 DQN 교체 근거를 위한 공정 비교 실험 (설계 + 실행 코드 + 합성 검증)

2026-10-07 · 기준 main `e0dd59fd912ae8f46eae1f3b5c96b14d98c05e54`.
이 디렉터리는 **설계와 하네스**이며 **운영 DQN 교체·배포·병합을 하지 않는다.** `research/time_constrained_planner/` 내부는 수정하지 않았다(쥴스 담당).

> **현재 판정: `SYNTHETIC_VALIDATION_ONLY`.** 공식 체크포인트(`dqn_final.pt`, sha256 `970aafbf…cbcf392`)는 저장소에 없고(`*.pt`는 gitignore) 사용자 허락 없이 내려받지 않았다. 아래 수치는 **대리(surrogate) DQN**으로 하네스가 동작함을 확인한 것이며 운영 DQN에 대해 아무것도 말해 주지 않는다. 공식 체크포인트로 실행하면 같은 코드가 `REPLACEMENT_EVIDENCE_SUFFICIENT/INSUFFICIENT/NOT_DECIDABLE` 중 하나를 낸다.

## 1. 정보 차이 (직접 비교하면 안 되는 이유)

| 항목 | 운영 DQN (`BunkeringEnv` 관측) | `time_constrained_planner.plan` |
|---|---|---|
| 현재 가격·MA30·환율 | 있음(정규화, [-1,1] 클립) | 있음 |
| **미래 가격** | **없음.** 가격은 σ=1%/step 랜덤워크 | **구간별 전체 가격 벡터를 미리 앎** |
| **구간 수요** | 없음(소모량은 env 상수) | **구간별 수요 벡터를 미리 앎** |
| 마감·항해시간 | 없음(시계 자체가 없음) | 시간 제한 `limit` 사용(항해시간 + 기항 시간) |
| 행동 | 이산 `1+n_ports`, 행동 1..3은 동일 → 사실상 이진 급유(0.9 또는 용량 한도까지) | 연속 구매량 + 이진 기항 |
| 초기 재고·예비 | env: 1.0 / 0.15 | 하드코드 0.5 / 0.1, 용량 1 |
| 비용 | 누적 구매비 (종료 재고 가치 **미반영**) | 구매비 `q·p`에 종료 재고 보정 `min(p)·(0.5−최종재고)`을 더한 값. **고정/가변 급유량은 시간(h) 제약이며 금전 비용 항목이 아니다**(`hours = sailing + v·q + f·(q>0) ≤ limit`) |

결론: 계획기는 오라클 정보와 연속 행동을 쓰므로 운영 DQN과 직접 비교하면 정보 이득을 알고리즘 성능으로 오인한다. 기존 NTNU 비교는 NTNU용으로 재학습한 DQN 대상이었고 운영 DQN이 아니다.

## 2. 설계

정보 단계(tier)를 분리한다. **교체 판정은 `I_ops`(운영 DQN과 같은 관측)만 사용한다.**

| tier | 계획기 | 용도 |
|---|---|---|
| `I_ops` | `planner_ops` — 현재 관측 + env 모델 상수만 쓰는 수신호 DP(메모리 없음, 지속(persistence) 예측) | **교체 후보(판정 대상)** |
| `I_ops_hist` | `planner_ops_hist` — 직전 관측으로 소모량 추정 | 확장(판정 제외) |
| `I_schedule` | `planner_ops_dl_*` — 마감 정보 추가 | 확장(판정 제외) |
| `I_forecast` | `planner_fcst_σ` — 참 미래 × 로그정규 노이즈 σ ∈ {0.005,0.01,0.02,0.05,0.1} | 가격 예측 오차 민감도(정보 가치) |
| `I_oracle` | `planner_oracle` — 참 미래 | 상한만, 후보 아님 |

- 같은 행동공간(이진 급유), 같은 env, 같은 시드, 같은 안전 감사(`VoyageAudit`).
- 비용 기준은 **재고 보정 SCI**(`inventory_adjusted_sci`)를 우선한다. 원 누적 비용지수는 종료 재고를 쳐 주지 않아 덜 사는 정책이 유리하다(아래 §6 참고).
- 계획기 파라미터(소모 0.05, 예비 0.15, 마진 0, 타이브레이크 순서)는 평가 전에 고정했고 어떤 평가 시드로도 조정하지 않았다. `planner_ops`는 env 동역학(소모량·보급 규칙·용량)을 구조 지식으로 사용한다. DQN은 이를 학습으로 얻는다.
- 평가 집합 3종(`criteria.json` `evaluation_sets`):
  - **기존 경로 재사용**(`scripts/evaluate.py` 계획, 시드 42–141, 100에피소드): 기본 학습 시드 범위(`seed+episode`, 42~5041)에 들어갈 수 있어 **판정에 쓰지 않고** 회귀·일치 검사에만 쓴다.
  - **개발 holdout**(시드 10,000,000–10,000,999): 설계 중 첫 시드의 단일 에피소드 결과를 보았고 첫 합성 검증에 전체가 쓰였다. 결과는 `results/synthetic_validation/`에 **보존**하되 판정에 쓰지 않으며 독립 확인이라고 부르지 않는다.
  - **확인(confirmation) 집합**(시드 40,000,000–40,000,999, 1,000에피소드): 후보·파라미터·임계값을 고정한 뒤 지정했고 어떤 실행·스모크·진단에서도 쓰지 않았다. **모든 통과/실패 판정은 이 집합만 사용**한다. 게이트 G2가 체크포인트 학습 시드 범위와 `seed_ranges_already_used`(재사용·개발·대리 학습·진단 시드) 비중복을 확인한다.
- 수요 오차: env의 실제 소모량을 ±10%, ±20%로 바꾸고 정책은 명목 0.05를 가정한다(필수 ±10%, 보고 ±20%).
- 가격·수요 예측 오차 민감도: 가격은 σ 격자(정보 가치 분석), 수요는 위 소모 불일치. 구간별 수요 변동은 env에 없어 **미구현(한계)**.
- **마감 분류**(시간 오버레이 `leg 24h`, `stop 8h`는 **합성 가정**이며 자료가 아님):
  - `sailing_exceeds_deadline`: 항해만으로 마감 초과 → **별도 집계, 준수율 분모 제외, 주장 없음.** 속도·항로 변경은 추가 가정이 필요한 별도 확장이며 구현하지 않았다.
  - `stop_forced_exceeds_deadline`: 항해는 되지만 안전 도착에 필요한 최소 기항 수가 마감 허용 기항 수보다 큼(시나리오별 DP로 계산) → 별도 집계.
  - `attainable`: 준수 판정 대상.

## 3. 사전 등록된 교체 판정 기준

`criteria.json`(sha256 `criteria.sha256`)에 평가 전에 고정했다. `evaluate.py`는 해시가 다르면 실행을 거부한다. **모든 수치 임계값은 `criteria.json`의 `thresholds` 블록이 단일 출처**이며 `decision.py`/`evaluate.py`가 이를 직접 읽는다(테스트: 임계값을 바꾸면 실제 판정이 바뀌고, 판정 코드에 수치 리터럴이 없음을 검사). 아래 표의 수치는 그 값의 요약이다:

| 기준 | 통과 조건 (확인 집합, `planner_ops` vs 운영 DQN) |
|---|---|
| R1 안전 | 계획기 depleted 0건 **그리고** 안전 도착률 차이의 95% 하한 ≥ −0.5%p |
| R2 비용 | 쌍별 재고 보정 SCI 상대 차이의 95% 상한 ≤ +0.5% (공동 안전 비율 ≥ 90%). 상한 < 0이면 "비용 우위", 아니면 "비열등"만 |
| R3 시간 준수 | `attainable` 마감 각각에서 정시 안전 도착률 차이의 95% 하한 ≥ −1%p |
| R4 실행시간 | 결정당 p99 ≤ 50 ms(측정 장비 기준, DQN 대비 배율은 참고) |
| R5 수요 강건성 | 필수 시나리오(±10%)에서 안전 도착률 차이 하한 ≥ −0.5%p |
| 게이트 | G1 공식 체크포인트 sha 일치, G2 확인 시드 비중복·미사용, G3 기준 해시, G4 확인 집합 ≥ 1000, G5 기존 `scripts.evaluate` 경로와 일치 |

G1 실패 → `SYNTHETIC_VALIDATION_ONLY`, 다른 게이트 실패 → `NOT_DECIDABLE`. 모두 통과해도 이는 **사람이 판단할 근거**이며 교체·배포·병합이 아니다. 가격 예측 기반 교체(R6)는 판정 기준이 아니다: 같은 예측을 DQN에도 주는 별도 평가가 필요하다.

기준 이력: **A2**(후속 PR) — 첫 합성 검증 뒤·공식 체크포인트 평가 전에 임계값을 `thresholds`로 옮기고(값 동일) 개발/확인 집합을 구분했다. 계획기 파라미터·지표·판정 논리는 바꾸지 않았다. **A1** — 평가 결과가 나오기 전, 한 에피소드 스모크 실행(시드 42, 10,000,000)에서 타이브레이크가 "예비 마진 우선"일 때 매 스텝 급유하는 퇴화 계획이 나와 순서를 (정지 수 → 마진)으로 바꾸고 `amendments`에 기록했다(커밋 `e33b791`).

## 4. 실행

```bash
# 1) (선택) 하네스 확인용 대리 DQN 학습 — 공식 모델이 아님
python -m research.fair_replacement_eval.train_surrogate --out /abs/path/surrogate.pt
# 2) 평가. 공식 체크포인트를 사용자가 직접 배치한 경우 그 경로를 넘긴다.
python -m research.fair_replacement_eval.evaluate --checkpoint /abs/path/dqn_final.pt \
    --out research/fair_replacement_eval/results/<name>
# 테스트
python -m pytest research/fair_replacement_eval -q
```

출력 폴더가 비어 있지 않으면 중단한다. 에피소드별 CSV(`episodes/`)는 gitignore이며 `manifest.json`에 sha256을 남긴다(결정론적이라 재실행으로 재현).

| 정책 | 안전도착률 | 평균 기항 | 재고보정 SCI 평균 | 원 누적비용지수 평균 |

| 대리 DQN | 100% | 5.89 | 976,687 | 877,823 |
| planner_ops | 100% | 1.00 | 976,283 | 487,973 |

- 원 비용지수로는 planner_ops가 44% 싸 보이지만 종료 재고 차이 때문이다. **재고 보정 비용 차이는 −0.04%(상한 +0.04%)로 사실상 0**이다. 1차(개발 holdout)의 +0.11%는 새 시드에서 재현되지 않았고(진단 시드 3,000건 t=0.36 포함) 우연으로 보인다.
- 가격·환율이 마팅게일이면 어떤 비예지 안전 정책도 기대 재고보정 비용이 같다. 따라서 **이 env에서는 비용이 아니라 안전·마감·실행·강건성이 교체 근거가 된다.** 가격 클립(250–850) 때문에 정확히 0은 아니다.
- R3(마감): 최소 안전 기항 1회. 700h `sailing_exceeds`, 720h `stop_forced`는 별도 집계(판정 제외), 728/736/760h가 `attainable`. 대리 DQN은 마감을 몰라 평균 5.9회 기항, 728/736h 정시도착 0%, 760h 68.9%. 계획기 100%. **"정지 수 최소" 타이브레이크 때문에 계획기에 구조적으로 유리**하며 공식 DQN 결과는 다를 수 있다.
- R4: 결정당 p99 계획기 1.31 ms, 대리 DQN 0.08 ms(이 장비 기준).
- R5: ±10%·±20% 모두 양쪽 안전도착 100%. 소모 +10%·+20%에서는 최소 기항이 2회가 되어 728h가 `stop_forced`로 바뀐다(`summary.json`의 `confirmation_time_by_scenario`).
- 정보 가치(가격 예측): 오라클은 `planner_ops` 대비 재고보정 비용 −1.86%. σ=0.005 −1.76%, 0.01 −1.54%, 0.02 −1.16%, 0.05 −0.49%, 0.10 −0.27%. **격자 안에서 절감이 사라지는 σ\*는 없었다(σ\*>0.1).** 이 예측 계획기는 운영 DQN이 받지 않는 정보를 쓰므로 교체 근거가 아니다.

1차(개발 holdout) 수치(안전 100%, 기항 5.60 대 1.00, 재고보정 SCI 973,474 대 974,578, 상대차 +0.113%, 오라클 −1.93%)는 `results/synthetic_validation/summary.json`에 그대로 있다.

## 6. 한계와 미검증

- **공식 DQN 평가 미실시.** 체크포인트가 없고 다운로드 허락이 없었다. 따라서 "DQN이 낫다/나쁘다/교체 가능"을 말할 수 없다.
- 대리 DQN은 학습이 덜 된 모델이며 하네스 검증용이다.
- 시간 오버레이(24h/8h, 마감 격자)는 **합성 가정**이다. env에는 시계·마감이 없다. 실선 항해시간·기항 소요와 연결되지 않았다.
- 수요는 상수 소모뿐이다. 구간별 수요 변동, 항구별 가격/공급 불확실성, 연속 구매량, 속도·항로 변경은 미구현이다(후자는 별도 확장).
- 가격은 env 랜덤워크(마팅게일)이므로 가격 타이밍 능력을 구분할 수 없다. 평균회귀·계절성이 있는 실제 시장에서는 결과가 달라질 수 있다.
- `planner_ops`는 env 동역학을 구조 지식으로 받는다(DQN은 학습). 모델 불일치(수요 오차)는 시나리오로만 봤다.
- 비교 시간 기준은 후보에 유리한 타이브레이크(기항 최소)를 포함한다. 최소화하지 않는 변형은 평가하지 않았다.
- R4 실행시간은 이 장비 기준이다. 다중 검정 보정 없음(모든 기준 AND).
- 스모크: 시드 42와 10,000,000(개발 holdout 첫 시드)의 단일 에피소드 결과를 설계 중 보았다(기록 §3). 진단용으로 시드 20,000,000–20,003,999(무행동 가격 경로)와 30,000,000–30,002,999(계획기 대 대리 DQN)도 썼으며 확인 집합과 겹치지 않는다.
- 테스트: `pytest research/fair_replacement_eval`(DP 전수열거 대조, 정보 차단 스텁, env 동역학 대조, 기존 evaluate 경로 일치, 판정 로직, 임계값 변경 시 판정 변경, 기준 해시 변조 거부). **통과 수는 Claude 실행 보고값이며 Codex 독립 재현은 완료되지 않았다**(Codex 환경에 pytest/gymnasium 미설치).
- 실제 절감, SCI의 통화 환산, DQN 우위/열위, 운영 교체 가능 여부는 주장하지 않는다.
